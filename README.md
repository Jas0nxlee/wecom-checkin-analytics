从企业微信「打卡」服务端 API 拉取员工打卡记录，本地生成一个可交互的分析看板：
**打卡时间分布 / 打卡地点热力图 / 出勤与异常趋势 / 工时加班负荷 / 部门与个人下钻**。

- 零第三方依赖：macOS/Linux、Python 3.8+（抓取与本地服务）+ 浏览器（图表库 ECharts 已内置到 `web/vendor/`）。跨进程锁使用系统fcntl。
- 地图无需任何 Key：GCJ-02坐标叠加高德栅格瓦片；断网时保留同一投影的坐标分布图，缩放和拖动保持一致。
- 官方口径优先：迟到/早退/缺卡/旷工/地点异常/设备异常取最新日报核定值；加班按已确认的19点后时段单独计算
- 业务数据本地保存：抓取结果落地 `data/*.json`、`data/*.csv`；地图底图仍会访问高德瓦片服务

指标定义与口径全部写在 **[docs/指标体系.md](docs/指标体系.md)**（含预警阈值、清洗规则、管理动作建议）。

## 接真实数据

### 1. 准备凭证

| 项目 | 获取位置 |
|---|---|
| `corpid` | 企业微信管理后台 → 我的企业 → 企业ID |
| `corpsecret` | 应用管理 → 自建应用 → Secret，**且该应用必须配置到「打卡 → 设置 → 可调用接口的应用」** |

```bash
cp config.example.json config.json   # 填入 corpid / corpsecret
# 或者：export WECOM_CORPID=ww... ; export WECOM_CORPSECRET=...
```

> 权限不足时接口会返回 `60011 / no permission`，脚本会把错误原样写进抓取日志，不会静默失败。
> 通讯录详情权限不是必需的：脚本会先尝试 `user/list_id` 只取 userid，再用打卡日报里的 `name` / `departs_name` 补全信息；如果这两个通讯录接口都不可用，需要显式传入 `--users userid1,userid2`。

### 2. 抓取

```bash
python3 fetch_checkin.py --start 2026-08-01 --end 2026-08-28   # 指定区间
python3 fetch_checkin.py --days 30                            # 最近 30 天（默认）
python3 fetch_checkin.py --days 30 --depts 1                  # 只取某个部门（需通讯录权限）
python3 fetch_checkin.py --days 30 --users zhangsan,lisi       # 只取指定人员
python3 fetch_checkin.py --days 30 --no-monthly --no-rules     # 只要打卡记录+日报，最快
```

产出：

```
data/checkin_data.json    看板唯一数据源（打卡记录 + 日报 + 月报 + 规则 + 人员）
data/checkin_records.csv  打卡原始记录（Excel 可直接打开核对）
data/checkin_daily.csv    打卡日报（迟到/早退/缺卡/旷工/地点/设备 次数）
```

接口硬限制已由脚本自动处理：单次时间跨度 ≤30 天（按 28 天分段）、`useridlist` ≤100 人（自动分批）、
记录 600 次/分、日报 100 次/分、月报 60 次/分（自动限速 + 45009 重试 + token 过期自动刷新）。

### 3. 打开看板

```bash
python3 server.py                      # http://127.0.0.1:8787
python3 server.py --port 9000 --host 0.0.0.0     # 局域网给 HR 看（自己评估暴露风险）
```

也可以直接在页面点 **「拉取新数据」**，填起止日期后台增量抓取并自动刷新看板（进度见抽屉）。

## 看板能回答的问题

- **总览**：全员出勤率、迟到率、缺卡率、保留零值的人均日工时、19点后加班、平均到岗/离岗偏移；可核定且可比较时提供环比和趋势
- **打卡时间**：0-23 时打卡分布、星期×小时热力、以标准班次为 0 点的到岗/离岗偏移直方图、按周箱线图、日历热力、部门×小时热力、首末打卡散点（短工/长工一眼可辨）
- **地点热力**：热力图 / 点位气泡 / 地点聚合三种模式，可按上班·外出·下班·仅异常筛选；地点类型构成、城市分布（含异常叠加）、距主办公点距离分箱、地点排行、人员活动地点多样性、WiFi 与设备分布
- **趋势对比**：出勤率/迟到率/缺卡率/早退率趋势（休息日断点而非按 0）、人均工时与加班、部门×日期出勤率热力、ISO 周环比、周内节律、月度对比
- **异常与人员**：异常构成、异常趋势、假勤/外勤结构、人均异常次数排行（点击进个人画像）、人×异常类型填色矩阵、可搜索排序分页的异常明细表
- **工时与加班**：官方日工时分布、有效连续在岗天数、19点后加班构成（工作日/休息日/排班待核定）、19点后加班排行、最晚离岗趋势（21/23 点后人数）
- **部门对比**：核定出勤/准点率分组柱 + 明细表，包含没有打卡记录的部门成员；不做加班越多越好的综合评分

## 常见问题

| 现象 | 处理 |
|---|---|
| `gettoken 失败 errcode=40013` | corpid 不对 |
| `checkin/getcheckindata 失败 errcode=60011 / no permission` | 该应用未配置到「打卡 → 可调用接口的应用」，或 Secret 用的是系统应用 Secret |
| `errcode=301002 / 48002` 通讯录失败 | 脚本会尝试 `user/list_id`；若仍失败，请给应用开通讯录权限，或显式传入 `--users userid1,userid2` |
| `errcode=60020` / `not allow to access from your ip` | 将当前出口 IP 加入企业微信管理后台对应的 IP 白名单，或改用允许访问的网络 |
| 地图只有网格没有街道 | 高德瓦片不可达（离线/内网），已自动降级为坐标分布图，指标不受影响 |
| 部分图表显示「暂无数据」 | 该筛选条件下无数据（例如选了「仅外勤」但没人外勤） |
| 数据很大（>10 万条）很慢 | 按月抓取（`--start/--end` 指定单月），或 `--users` 分批；接口本身也要求 30 天分段 |
| 想给团队看 | `python3 server.py --host 0.0.0.0 --port 8787`，注意打卡数据属员工个人信息，请控制访问范围 |

## 合规提示

打卡位置、WiFi、设备号、人脸附件（`mediaids`）都属于个人信息：
仅在企业微信应用可见范围内抓取，抓取结果建议只放本机/内网，明细表按需按部门筛选，
不要在页面公放；如需展示给无关人员，可先在前端做姓名脱敏。

# 打卡分析指标体系 v2

确认日期：2026-08-31。以下业务口径由项目管理者确认，优先于旧版演示口径。

## 1. 已确认的业务规则

- 应考勤人员：企业微信当前通讯录中，排除“其他人员、辅助账号、董事长、总经办”四个部门及其成员，人数动态更新。按当前任一部门归属精确匹配，不按历史旧部门或相似名称误排除。不能只取有打卡记录的人员。
- 调休、节假日、轮班：使用企业微信当日日报、员工当日规则及个人排班表；不凭星期或第三方节假日库猜测。
- 日报实际工作时长为0：保留0，不能用打卡跨度替换；字段缺失是未知。
- 加班：有效到岗至离岗区间在19:00之后的部分，不是审批加班或计薪加班。晚于19:00到岗，从到岗时间算起。不额外推断晚间休息。
- 历史部门归属：使用当前组织关系。
- 访问：管理层内部使用，本版不做部门角色登录；默认仅监听本机，内网部署由网络环境限制访问。
- 补卡：允许本月追溯，审批通过自动同步；时间和地点使用最新核定结果整体更新。
- 时区：Asia/Shanghai（UTC+8）。

## 2. 数据分层

1. 原始记录：保留未打卡占位、原地点和原异常，不篡改轨迹。实际打卡动作图不计“未打卡”占位。
2. 审批过程：从企业微信审批API取得补卡申请状态、归属日期、卡位时间和申请编号。只保存补卡的必要字段，不保存审批正文或附件。
3. 有效人日：当前人员 × 筛选日期的完整底表，关联日报、规则和补卡状态。无原始打卡但有日报/请假/补卡的人员不消失。

服务端统一应用部门排除范围，覆盖人员下拉、全部指标、明细、规则、补卡记录和CSV导出。原始JSON及抓取历史保持全量，便于恢复；直接离线分析原始JSON时，应先调用checkin_policy.apply_attendance_scope。恢复部门只需调整POLICY.excluded_departments并重新加载，无需找回被删除的数据。

原始异常不能覆盖已补正的官方结果。日报字段不是审批明细，单有“补卡次数”不能说明每张申请的状态。

## 3. 排班与数据覆盖

- 优先使用日报day_type区分工作与休息；完整班次段保留在segments。
- 规则特殊工作日和休息日直接使用企业微信返回值。
- 按班次上下班时使用个人排班表。休息班次是明确休息，不返回该日期是未知。
- 规则的sync_holidays只说明自动节假日开关；没有当日日报或明确特殊日期时，不将开关本身当作某天日历。
- 缺少部分排班/工作日日报时，仅将对应人日暂不纳入比率；其他已核定人日正常计算出勤、迟到、早退、缺卡及准点率。分子和分母必须使用同一核定集合，不能混入缺日报的原始打卡。
- 只有没有任何核定应出勤人日时，比率才显示“—”。显示名称为“出勤率（已核定）”，不能冒充缺口已补齐的全员最终率。
- 依据覆盖率 =（完整人员日期底表 − 依据缺口人日）÷ 完整底表人日。已明确休息日属于有依据；缺排班与缺日报重叠不重复计数。
- 未知日期保留在人员底表并可查看，不计为缺勤或休息，也不把首次出现日报/打卡的日期推断成入职日期。实际入职或考勤生效日期仍需可信依据。
- 即使接口缺少某些员工的数据，这些员工仍在人数、部门和个人底表中。需要在企业微信配置规则或可见范围后重拉。
- 请假单独展示，未打卡不直接推断旷工；旷工只能取最新日报核定值。
- 出勤率是实际出勤覆盖率，不是“合规率”。本版应出勤分母不另行扣除请假人日。

## 4. 核心指标

| 指标 | 定义 |
|---|---|
| 应考勤人数 | 当前筛选部门的通讯录全员；打卡规则筛选按匹配人日归属 |
| 应出勤人日 | 企业微信核定为工作日的人员日期组合 |
| 有效出勤人日 | 日报有核定打卡次数/实际工作时长，或日报已应用且无剩余异常的补卡；仅有原始占位不算出勤 |
| 核定应出勤人日 | 已知为工作日且有官方日报的人员日期组合，是各类考勤比率的共同分母 |
| 出勤率（已核定） | 核定应出勤集合中的有效出勤人日 ÷ 核定应出勤人日；缺口单列，不阻断已有依据的计算 |
| 准点率（核定） | 核定集合中已出勤且最新日报没有迟到的人日 ÷ 核定应出勤人日；不再用原始钟点推翻补卡核定 |
| 迟到/早退/缺卡率 | 核定集合中有对应异常的人日 ÷ 核定应出勤人日；一天多次异常在分子仅算1个人日 |
| 考勤依据覆盖率 | 有明确工作/休息依据且工作日有日报的人日 ÷ 当前人员×区间自然日；含休息日，不是出勤率 |
| 异常次数/时长 | 日报对应异常count/duration，内部时长统一为秒；与异常人日率分开展示 |
| 人均日工时 | 已取得官方工时的工作日日报实际工时合计 ÷ 该类日报人日数；包含官方0值，不填补缺失 |
| 标准日工时 | 已取得标准工时的工作日日报standard_work_sec均值；不取第一段班次减固定午休 |
| 19点后加班 | max(有效离岗时刻 − max(有效到岗时刻,19:00),0)；时长以秒存储，显示小时 |
| 加班时刻缺口 | 已出勤但不能核定成对到离岗时刻的人日；不自动补足到19:00或24:00 |
| 平均到岗/离岗 | 优先日报核定最早/最晚时刻，缺少时由真实卡辅助；跨夜按排班归属日保留次日偏移 |
| 外勤打卡占比 | 外出实际打卡动作数 ÷ 全部实际打卡动作数，不是外勤人数比例 |
| 人均异常次数 | 核定工作日异常次数 ÷ 核定应出勤人日，单位次/人日；无核定分母时为空 |
| 连续在岗 | 连续自然日存在有效出勤；占位、休息无出勤与未知日期不接成连续在岗 |

工时与19点后时长是两个独立口径：前者来自官方工时字段，后者来自有效到离岗时刻。不能把19点后加班与“标准工时内”堆叠成总工时。

## 5. 补卡生命周期

| 状态 | 展示与计算 |
|---|---|
| 待审批 | 单独标识待审批，不能提前清除当前核定异常 |
| 已通过，日报旧于审批同步 | 待同步，不直接伪造正常 |
| 已通过且新日报正常 | 已补正正常；有效异常不再计数，原始轨迹保留 |
| 已通过且新日报仍有异常 | 已同步但仍有核定异常，不自行把整日清零 |
| 驳回/撤回/通过后撤销 | 保留最新申请状态，有效结果以最新日报为准 |
| 审批接口失败 | 明示未同步/不完整，保留旧申请；不当作无申请 |

申请提交日期和考勤归属日不同。关联键包含人员、考勤日期、卡位和申请编号。一个申请可能有多个卡位，卡位数量不是申请单数量。
页面“仅异常”地图使用最新有效异常；“原始异常”用于回溯，不用于替代当前核定结果。

## 6. 比较、筛选和图表

- 所有日期/周/月/人员/部门比率共用同一聚合函数，缺卡2次仍只算1个异常人日。
- 顶部环比采用区间首尾等长自然日窗，奇数天时不使用中间那天参与比较；两窗分别计算分母。
- 两窗中只要存在依据缺口，当前考勤比率仍显示，但环比标为“覆盖不齐，暂不环比”，防止把样本变化当改善/恶化。日、周、月、部门及个人仍按各自核定集合展示，并保留覆盖信息。
- 周/月首尾可能不完整；图表属于筛选范围汇总，不冒充完整月度同比。
- 没打卡的日期保留在时间轴；未知值断点，不填0。
- 部门按当前组织关系；原始CSV按当前日期、部门、规则筛选导出。
- “仅上下班/仅外勤”只控制原始打卡与地点图，有效考勤仍保留全天与全员分母。
- 部门对比不使用“加班越多越好”的雷达综合评分。
- 主办公点与距离分布只是探索线索。地图不再显示“企业微信规则范围”选项或范围圈，后台规则数据仍用于考勤。
- 地图提供柔和热力、蓝色密度、点位气泡和地点聚合。两种密度图共用浮点高斯平滑结果，按当前视野归一化；柔化滑块只调整视觉扩散，不代表实际距离、打卡允许范围或考勤结论。
- 滚轮/触摸板先累计增量，达到阈值后最多变化一级，并设240毫秒冷却；以鼠标位置为缩放锚点。在线和离线采用相同投影。
- 地图会请求高德瓦片，业务记录不主动上传；不应宣称完全无外部网络请求。

## 7. 采集和回补

- 原始记录/日报按28天、100人拆分。规则按日期和100人获取。
- 补卡列表使用record_type=2，仅取补卡申请，按new_cursor翻页后读取详情。
- 页面抓取会回补本月已结束日期，读取当前月审批并随后重拉日报，以取得审批生效后的结果。
- 命令行显式历史区间按指定范围抓取；需要回补本月时加--refresh-month。
- 只替换请求成功的人员、日期和接口分片。接口失败、跳过日报或只拉部分人时不得删除其他数据。
- 月报存query_start/query_end，不读取接口没有提供的base_info.date当月份；月报不参与19点后加班计算。
- 主JSON原子替换，保存checkin_data.json.previous。CSV同样原子写入，空数据写表头，防止旧数据残留。
- 当前快照带schema_version、dataset_version、采集覆盖和审批同步状态；同条数更新也失效前端缓存。
- 旧版日报丢失的班次段无法本地还原，应重拉对应日期；页面不再将上午下班错误当全天标准下班。
